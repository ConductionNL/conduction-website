## The four pillars

Almost every Conduction tutorial leans on one of four pillars. Pick the one that matches your first real task:

<HexCard title="OpenSpec — spec-first development">
  Every change to every app starts as a spec. Two short modules (~30 min total) teach you the concepts and walk you through your first change.
</HexCard>

<HexCard title="Claude Skills — bundled AI behaviour">
  Custom slash-commands that Claude Code loads on demand. Four short modules teach you to read and write skills, and the maturity framework we measure them against.
</HexCard>

<HexCard title="Build an App — your first published app">
  A 30-minute teaser that takes you from a fresh Nextcloud to a published app. Or the longer DeskDesk series for the proper tour.
</HexCard>

<HexCard title="Hydra — agentic CI/CD pipeline">
  The platform that turns OpenSpec changes into reviewed, tested PRs. Six modules; mostly relevant once you're comfortable with the first three pillars.
</HexCard>

## Which one first?

Honest answer: **OpenSpec, then either Skills or Build an App, then Hydra last**. The order matters because:

- OpenSpec is the substrate. Every change to every app — including the next four tutorials' worth of changes — is shaped as an OpenSpec change. Skipping it makes the rest harder to read.
- Skills and Build an App are sideways from each other. Pick the one closer to your first task.
- Hydra is the most opinionated and the most internal. Save it for when you're confident with the previous three.

### If your first task involves writing actual code

Start with **[OpenSpec Part 1](/academy/openspec-tutorial-1-wat-is-openspec)** (~12 min) — what OpenSpec is, the four core concepts. Then **[OpenSpec Part 2](/academy/openspec-tutorial-2-eerste-change)** (~22 min) — your first change end-to-end.

After that, jump to **[Build an App](/academy/build-an-app)** for the 30-minute teaser, or **[DeskDesk Tutorial 0](/academy/deskdesk-tutorial-0-three-paths)** if you want the honest map of how Conduction apps actually get built (it lists three paths and explains why we teach the third).

### If your first task involves writing tooling or skills

Start the same way — **[OpenSpec Part 1](/academy/openspec-tutorial-1-wat-is-openspec)** and **[Part 2](/academy/openspec-tutorial-2-eerste-change)** — because skills are versioned and specified the same way as app code. Then go to **[Claude Skills Part 1](/academy/claude-skills-tutorial-1-wat-zijn-claude-skills)** (~12 min) — what a skill is, when not to write one. **Parts 2–4** of that series take you through writing your first skill and the maturity framework that turns "feels good" into "measured good".

### If your first task is about Hydra itself

You still want OpenSpec under your belt first. After that, **[Hydra Part 1](/academy/hydra-tutorial-1-wat-is-hydra)** (~10 min) — what Hydra is, four container personas, when not to use it. The series has six parts; budget an afternoon for the full read.

## What's *not* covered by these tutorials

A few areas you'll meet at Conduction that don't have a dedicated tutorial series yet:

- **The day-to-day Claude Code workflow** — the [getting-started.md](https://github.com/ConductionNL/.github/blob/main/docs/claude/getting-started.md) doc in the `.github` repo is the closest to a single-page workflow primer.
- **Frontend standards** — covered in [frontend-standards.md](https://github.com/ConductionNL/.github/blob/main/docs/claude/frontend-standards.md). Worth a skim before your first Vue PR.
- **Testing skills in depth** — `/test-app`, `/test-counsel` and the `hydra-gate-*` family are documented in [testing.md](https://github.com/ConductionNL/.github/blob/main/docs/claude/testing.md). Read on demand, not upfront.
- **The local LLM workflow (Ollama + Qwen)** — see [local-llm.md](https://github.com/ConductionNL/.github/blob/main/docs/claude/local-llm.md). Optional, useful if you want overnight batch jobs.

These are reference docs, not tutorials. Use them when a specific question comes up; don't try to read them upfront.

## A note on Pluvo

Every Conduction tutorial in the academy ends with the **Test yourself** quiz block — five questions per part with Hint and Answer fold-outs. Internally we call those **Pluvo questions** (after the spaced-repetition tool we use). The answers are not exam questions; they're a self-check that the part actually landed. If you blank on three out of five, the part is probably worth a re-read.

For this series specifically, the Pluvo questions cover:

| Part | Sample question |
| --- | --- |
| 1 — Overview | Which OS + tooling combination does Conduction recommend, and why? |
| 2 — Basics | Why install Node and PHP inside WSL rather than on the Windows side? |
| 3 — Claude Code | What's the difference between global and project-level Claude settings? |
| 4 — MCP | Which two settings pre-approve the MCP browsers so background agents aren't blocked? |
| 5 — Nextcloud | When to reset the local Nextcloud, and when to keep the existing state? |
| 6 — What now? | (the questions below) |

Spend ten minutes on the Pluvo blocks before declaring a part "done" — that's the easiest way to make this knowledge stick.

## How long does this all take?

A rough honest estimate, on a clean Windows machine:

- **This workstation series**: one evening (~3 hours clock, ~1 hour hands-on).
- **OpenSpec Parts 1+2**: one short session (~45 minutes).
- **Claude Skills Parts 1–2 or Build an App**: one evening (~2 hours).
- **First real Conduction PR**: another evening (~2 hours of pair work with someone who already knows the stack).

So roughly **three evenings** from clean laptop to first merged PR. That's the target; it varies with how much terminal + Git muscle memory you bring in.

**3. Why is the Hydra tutorial series saved for *after* OpenSpec, Skills, and Build an App?**

<Details summary="Hint">

Two reasons — one about prerequisites, one about scope.

</Details>

<Details summary="Answer">

Two reasons:

1. **Hydra builds on top of OpenSpec and Skills.** It runs `/opsx-*` skills against OpenSpec changes inside containers. Without those two pillars first, the Hydra tutorials read like a foreign language.
2. **It's the most internal and most opinionated of the four pillars.** Many new developers won't touch Hydra in their first month; the ones who do should already be comfortable with the rest of the stack.

So: OpenSpec → Skills (or Build an App) → Hydra. If you want a one-pager preview before reading the full series, the [hydra/README.md](https://github.com/ConductionNL/.github/blob/main/docs/hydra/README.md) in the `.github` repo is a good warm-up.
