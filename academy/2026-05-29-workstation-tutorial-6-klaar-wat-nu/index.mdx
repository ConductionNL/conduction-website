## The four pillars

Almost every Conduction tutorial leans on one of four pillars. Pick the one that matches your first real task:

<HexCard title="OpenSpec — spec-first development">
  Every change to every app starts as a spec. Two short modules (~30 min total) teach you the concepts and walk you through your first change.
</HexCard>

<HexCard title="Claude Skills — bundled AI behaviour">
  Custom slash-commands that Claude Code loads on demand. Four short modules teach you to read and write skills, and the maturity framework we measure them against.
</HexCard>

<HexCard title="Build an App — your first published app">
  A nine-part series (Parts 0–8) that takes you from a fresh Nextcloud to a published, documented app via the PetStore domain. Starts with the three architectural paths and teaches the manifest path end to end.
</HexCard>

<HexCard title="Hydra — agentic CI/CD pipeline">
  The platform that turns OpenSpec changes into reviewed, tested PRs. Six modules; mostly relevant once you're comfortable with the first three pillars.
</HexCard>

## Which one first?

Honest answer: **OpenSpec, then either Skills or Build an App, then Hydra last**. The order matters because:

- OpenSpec is the substrate. Every change to every app — including the next four tutorials' worth of changes — is shaped as an OpenSpec change. Skipping it makes the rest harder to read.
- Skills and Build an App are sideways from each other. Pick the one closer to your first task.
- Hydra is the most opinionated and the most internal. Save it for when you're confident with the previous three.

### If your first task involves writing actual code

Start with **[OpenSpec Part 1](/academy/openspec-tutorial-1-what-is-openspec)** (~12 min) — what OpenSpec is, the four core concepts. Then **[OpenSpec Part 2](/academy/openspec-tutorial-2-first-change)** (~22 min) — your first change end-to-end.

After that, jump to **[Build an App tutorial — Part 0](/academy/build-an-app-tutorial-0-three-paths)** for the honest map of how Conduction apps actually get built (three paths, why we teach the manifest path). Then walk Parts 1–8 — scaffold, schemas, calendar, integrate, ship — using the PetStore as the running domain.

### If your first task involves writing tooling or skills

Start the same way — **[OpenSpec Part 1](/academy/openspec-tutorial-1-what-is-openspec)** and **[Part 2](/academy/openspec-tutorial-2-first-change)** — because skills are versioned and specified the same way as app code. Then go to **[Claude Skills Part 1](/academy/claude-skills-tutorial-1-what-are-claude-skills)** (~12 min) — what a skill is, when not to write one. **Parts 2–4** of that series take you through writing your first skill and the maturity framework that turns "feels good" into "measured good".

### If your first task is about Hydra itself

You still want OpenSpec under your belt first. After that, **[Hydra Part 1](/academy/hydra-tutorial-1-what-is-hydra)** (~10 min) — what Hydra is, four container personas, when not to use it. The series has six parts; budget an afternoon for the full read.

> **Follow along — clone Hydra now.** If you have access to the private [`Conduction/hydra`](https://codeberg.org/Conduction/hydra) repo (ask your team lead if not), clone it before you start so you can open files referenced in the series as you read:
>
> ```bash
> git clone git@codeberg.org:Conduction/hydra.git
> cd hydra
> ```
>
> Reading-only is fine — the clone only becomes a hard requirement at [Hydra Part 5](/academy/hydra-tutorial-5-starting-a-run), where you trigger an actual run.

## What's *not* covered by these tutorials

A few areas you'll meet at Conduction that don't have a dedicated tutorial series yet:

- **The day-to-day Claude Code workflow** — the [getting-started.md](https://codeberg.org/Conduction/.github/src/branch/main/docs/claude/getting-started.md) doc in `Conduction/.github` on Codeberg is the closest to a single-page workflow primer.
- **Frontend standards** — covered in [frontend-standards.md](https://codeberg.org/Conduction/.github/src/branch/main/docs/claude/frontend-standards.md). Worth a skim before your first Vue PR.
- **Testing skills in depth** — `/test-app`, `/test-counsel` and the rest of the testing workflow are documented in [testing.md](https://codeberg.org/Conduction/.github/src/branch/main/docs/claude/testing.md). The `hydra-gate-*` family lives in `hydra/.claude/skills/` in the [hydra repo](https://codeberg.org/Conduction/hydra) — closer to the gates themselves. Read on demand, not upfront.
- **The local LLM workflow (Ollama + Qwen)** — see [local-llm.md](https://codeberg.org/Conduction/.github/src/branch/main/docs/claude/local-llm.md). Optional, useful if you want overnight batch jobs.

These are reference docs, not tutorials. Use them when a specific question comes up; don't try to read them upfront.

## How long does this all take?

A rough estimate, based on the reading times the tutorials themselves list:

- **This workstation series**: one evening (the six parts together are well under an hour of reading, but plan for installs and the first run of each piece).
- **OpenSpec Parts 1+2**: ~35 minutes of reading (12 + 22), plus the time to actually do the first change.
- **Claude Skills Parts 1+2**: ~30 minutes of reading (12 + 18). The full four-part track adds Parts 3 and 4 on top.
- **Build an App tutorial Part 0**: ~15 minutes for the architectural overview. The full 9-part series spans multiple evenings.

Add a Conduction colleague pairing with you on a first real change, and "clean laptop to first merged PR" is realistically a few evenings of mixed reading and doing. Your mileage will vary with how much terminal and Git muscle memory you bring in.

**1. What's the first tutorial series you do *after* finishing this Workstation Setup chain — and why that one?**

<Details summary="Hint">

It's the substrate underneath everything else.

</Details>

<Details summary="Answer">

**The [OpenSpec tutorial series](/academy/openspec-tutorial-1-what-is-openspec)** — two short parts, ~30 minutes total.

Why first: every change to every Conduction app — including the tutorials *after* OpenSpec — is shaped as an OpenSpec change. Skipping it makes the rest of the academy harder to read because you'll be guessing at the structure of every `proposal.md`, `tasks.md` and spec-delta you see.

</Details>

<div className="tutorial-quiz">

**2. Your first task is to write a Claude Skill. You're tempted to skip OpenSpec and dive straight into the Skills series — after all, the task isn't about app code. Why is that probably a mistake?**

<Details summary="Hint">

How does a skill itself get tracked, reviewed, and changed at Conduction? Look at how the existing skills in `hydra/.claude/skills/` are version-controlled.

</Details>

<Details summary="Answer">

Because skills are versioned and specified the same way as app code. Every skill at Conduction lives in `.claude/skills/<name>/SKILL.md`, and a non-trivial change to a skill goes through the same OpenSpec workflow as an app feature: proposal → spec-delta → tasks → review.

If you skip OpenSpec, the first time you propose a skill change you'll see the reviewer ask *"where's the spec-delta?"* and you'll be back-filling concepts that 30 minutes of OpenSpec Parts 1+2 would have given you upfront. The Skills tutorial series even references `proposal.md`, `tasks.md` and `spec-delta` as if you already know what they mean — because it assumes you've done OpenSpec first.

Spec-first applies to *everything Conduction ships, including the tooling that ships the things*. Skipping OpenSpec for skill work is like skipping Git for solo work — you can do it, but you're paying the cost later in a less convenient form.

</Details>

</div>

<div className="tutorial-quiz">

**3. Why is the Hydra tutorial series saved for *after* OpenSpec, Skills, and Build an App?**

<Details summary="Hint">

Two reasons — one about prerequisites, one about scope.

</Details>

<Details summary="Answer">

Two reasons:

1. **Hydra builds on top of OpenSpec and Skills.** It runs `/opsx-*` skills against OpenSpec changes inside containers. Without those two pillars first, the Hydra tutorials read like a foreign language.
2. **It's the most internal and most opinionated of the four pillars.** Many new developers won't touch Hydra in their first month; the ones who do should already be comfortable with the rest of the stack.

So: OpenSpec → Skills (or Build an App) → Hydra. If you want a one-pager preview before reading the full series, the [hydra/README.md](https://codeberg.org/Conduction/.github/src/branch/main/docs/hydra/README.md) in the `.github` repo is a good warm-up.

</Details>
